Generate a QR code Host it on GitHub Pages

Printing a QR code on a flyer, business card, or event program only works if the code actually leads somewhere reliable. The usual approach — pasting a PDF into some random online converter — means trusting a stranger's server with your document and hoping the link doesn't rot in six months.

This tool takes a different approach: it builds the QR code entirely in your browser, and it's honest about the one real constraint in this whole process — a QR code can only hold about 2–3 KB of data. That's plenty for a link, but nowhere near enough for a typical multi-page PDF. So for any normal-sized file, the QR code encodes a direct link to your PDF once it's hosted somewhere public, like a GitHub Pages repository you already control. Scan the code, the browser opens that exact link, and your PDF loads. For the rare genuinely tiny PDF — a single-page voucher or a short note — the tool can embed the file's data directly into the QR code instead, so no hosting is needed at all.

Because you're hosting the file yourself, you keep control of it permanently: update the PDF whenever you want without reprinting a single QR code, since the link stays the same even if the content behind it changes.

Hosting your PDF on GitHub Pages

If your site is already live on GitHub Pages, this is the fastest place to put the PDF so the QR code has something real to point to.

  1. Create a files folder

    In your repository's root directory, add a new folder named files.

  2. Add your PDF using the suggested filename

    Upload your PDF into that folder, named exactly as shown in the generator above — lowercase, hyphenated, no spaces.

  3. Commit the change

    Commit straight to your main branch, or merge it in if you're working from a pull request.

  4. Wait for the rebuild

    GitHub Pages redeploys automatically after each commit. This usually takes about a minute, occasionally longer.

  5. Generate the QR code and test it

    Enter the full URL — something like https://yourname.github.io/yourrepo/files/your-file.pdf — into the generator, then scan the result yourself before printing or sharing it anywhere.

Frequently asked questions

Can a QR code actually contain an entire PDF file?+
Only if the PDF is very small, roughly under 1.5 KB. QR codes top out around 2–3 KB of raw data, and most real PDFs are far larger. For anything bigger, the QR code holds a link to the PDF instead of the file itself, which is what this tool does by default.
Does this tool upload my PDF anywhere?+
No. The PDF is read locally in your browser to check its size and generate the QR code. Nothing is sent to a server unless you separately choose to upload it yourself — for example to your own GitHub repository.
Why does my QR code lead to a broken link?+
The usual causes: the PDF hasn't been committed yet, the filename doesn't exactly match — including capitalization — GitHub Pages hasn't finished redeploying (give it a minute or two), or the folder path in the URL doesn't match where the file actually lives.
What filename should I give my PDF?+
Lowercase letters, numbers, and hyphens only, no spaces, and keep the .pdf extension. The generator suggests a safe filename automatically — that exact name is what needs to match the URL encoded in the QR code.
Can I use a custom domain instead of github.io?+
Yes. Just replace the URL in the generator's link field with wherever the PDF will actually be hosted — a github.io address, a custom domain pointed at GitHub Pages, or any other file host.
Will the QR code work before I upload the PDF?+
Not if you're using the link method. The QR code encodes a URL, and that URL will 404 until the PDF actually exists at that exact path in your live repository.
